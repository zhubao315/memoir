# 架构决策记录 (ADR)

## ADR-001 — 模块化单体，不引入微服务
- 状态：已采用
- 原因：当前规模与团队不需要微服务；任务书明确禁止过度工程化。采用 `backend/app/` 分层 + 独立 Worker 进程。

## ADR-002 — 保留 legacy API，不推倒重写
- 状态：已采用
- 原因：保护现有用户与数据；新能力走 `/api/v1/*`，旧路径 `/api/*` 原样保留。前端 SPA 逐步迁移，旧 `index.html` 保留回退。

## ADR-003 — 原始数据与 AI 衍生内容分离
- 状态：已采用（原则 A）
- 原因：录音/逐字稿是不可替代资产。录音无 update 接口；AI 故事写入 `story_versions`，人工编辑新建版本，从不覆盖原始内容。

## ADR-004 — AI Provider Adapter + 诚实的 Mock
- 状态：已采用
- 原因：无 API Key 是常态。Mock 明确声明离线、不联网、输出带“离线 Mock 转录”标记，绝不把固定文本伪装成真实 AI 服务。业务代码只依赖抽象接口，模型/URL/Key 全部环境变量化。

## ADR-005 — Alembic 幂等初始迁移 + 非破坏性数据复制
- 状态：已采用
- 原因：任务书「不删旧库、不覆盖、可回滚」。`0001_initial` 用 `create_all(checkfirst=True)` 只补缺表；迁移脚本只 INSERT 不存在的行，保留 UUID/时间/hash。downgrade 故意为 no-op，回滚走备份恢复流程。

## ADR-006 — 媒体访问用签名 URL + 所有权校验
- 状态：已采用
- 原因：修复原有无鉴权/端点缺失。私有存储 + 短期 HMAC 签名 URL（本地）/ S3 presigned URL；二维码用稳定不可预测 token，可撤销，公开页仍校验可见范围。

## ADR-007 — 数字遗产不自动交付
- 状态：已采用
- 原因：任务书反复强调。必须显式授权 + 身份核验 + 人工审核 + 可撤销 + 争议状态；绝不因长期未登录自动交付。

## ADR-008 — 前端用 React+TS+Vite，但保留旧静态页回退
- 状态：已采用
- 原因：任务书推荐技术栈；构建产物在 `frontend/dist`。旧 `frontend/index.html` 不再作为主入口但保留，部署切换由 Nginx 配置控制。
